# F9 results — the gate holds, Docling is not justified, and my metric was wrong

Three things were measured. Two came back clean, one came back as a correction to the F9
spec itself.

## 1. The zero-fabrication gate holds, twice

| | Target | Measured |
|---|---|---|
| Correct abstention on `unanswerable` | 5 / 5 | **5 / 5** |
| Citations naming a passage never sent | 0 | **0** |
| Answers fabricating a source | 0% | **0%** |

Reproduced across **two independent full runs** of all 36 questions through Llama 3.1 8B.

`unanswerable-tungsten` is the one worth naming. The melting point of tungsten is not in
the corpus and *is* in the model's weights, so answering it would not be hallucination in
the usual sense — it would be the model being helpful with knowledge it was told not to
use. A system that answers it will answer a question about a customer's contract the same
way. It abstained in both runs.

## 2. Docling is not justified by this corpus

The count that decides it:

```
table questions                 5
anchors lost by pdfplumber      0
```

Extraction rate is **100%** across all 31 answerable questions. Every fact the question set
names survives pdfplumber, so there is nothing on this corpus for a layout-aware parser to
recover. M0 deferred this decision twice rather than install a heavy dependency on taste;
the answer is that on these documents it would buy nothing measurable.

**This is a verdict about the corpus, not about Docling.** The eval set is public
regulations and papers whose tables are mostly well-formed and text-based. A scanned
customer table would very likely fail, and `Route.LAYOUT` still fires for two-column pages.
The right next step is not to install Docling but to put a genuinely hostile table in the
corpus and re-run this one command.

## 3. The context ceiling: 90%

The number this milestone existed to produce.

| Stage | Rate | |
|---|---|---|
| Extraction — the anchor survives parsing | **100%** | |
| Context — it reaches the model in the top 8 | **90.3%** | the ceiling |

| Type | Extraction | Context |
|---|---|---|
| factual | 100% | **100%** |
| table | 100% | **100%** |
| cross-document | 100% | 80% |
| identifier | 100% | 66.7% |

No model can state a fact that was not in its context, so 90% is the hard bound on answer
quality with today's retrieval. Three questions account for the whole gap:
`cross-platform-obligations`, `identifier-catalog-number`, `identifier-usc-citation`.

**A defect in the harness was found producing this number.** The first run reported 67.7%,
because passing `reranker=None` to `SearchService` means *build the default*, which then
failed to reach TEI and degraded. The ceiling was being measured against a search nobody
runs. Recorded because the failure mode is the one this project keeps warning about — a
silently worse answer that still looks like a result.

## 4. My accuracy metric was wrong, and the spec said so first

F9's spec predicted anchor-containment would be an **upper bound** on correctness, on the
reasoning that containment is lenient. The first run disproved it:

| Anchor | Answer | Scored |
|---|---|---|
| `DensePassageRetriever` | "Dense Passage Retriever (DPR)" | MISS |
| `this is Bank Rate` | a correct definition of Bank Rate | MISS |
| `Designation of the data protection officer` | "must designate a Data Protection Officer" | MISS |

Two fixes, of different kinds. **Typography is now handled** — `contains` retries on
alphanumerics only, withheld from anchors containing digits because squashing `1.45%` to
`145` would start matching page numbers. **Paraphrase is not handled and cannot be**: an
anchor lifted from a section heading will never appear verbatim in good prose.

So the metric is renamed to what it measures — `quotation_rate` — and it is **neither an
upper nor a lower bound on correctness**.

### Hand-verified correctness

All 16 unquoted answers were read against their sources:

| | Count |
|---|---|
| Correct, but paraphrased so the anchor check missed it | **10** |
| Genuinely wrong or incomplete | 6 |

| Measure | Value |
|---|---|
| `quotation_rate` (automated) | 45.2% |
| **Hand-verified correctness** | **~77%** (24 / 31) |
| Context ceiling | 90.3% |

The 77% assumes the 14 quoted answers are correct, which was not checked individually —
quoting the exact source phrase is strong evidence but not proof.

The six real failures are worth naming, because they are a pattern rather than noise:
`cross-retrieval-vs-pretraining`, `cross-platform-obligations` and `cross-payroll-and-return`
each answer one half of a two-part question and drop the other. `table-form-1040-status`
answers a different question than the one asked. `identifier-oj-page` and
`identifier-usc-citation` recite surrounding text without stating the fact.

**That is an 8B model failing at multi-part questions, not a retrieval failure** — the
context ceiling says the material was in front of it. It is exactly what §5.4 predicted by
fixing the dev model at the floor rather than the ceiling.

## 5. Latency, measured honestly for the first time

Median **11.1 s** per answer, end to end: query embedding, hybrid retrieval, cross-encoder
rerank of 50 candidates, and 8B generation over 8 passages — all on one laptop, all
sequential.

Previous evaluations reported per-query latency and both write-ups correctly said the
numbers meant nothing. **The reason is now known and fixed**: `LocalEmbedder.encode`
constructed a `SentenceTransformer` on every call, so every query in every past evaluation
reloaded two gigabytes of weights before doing any work. F6's 4.8 s and F7's 8.6 s were
measuring `from_pretrained`.

This 11.1 s is still not a product number — a real deployment has a warm TEI and a GPU, and
generation dominates regardless.

## 6. What this leaves for the next milestone

1. **Multi-part questions.** Six of six real failures involve either two documents or two
   asked-for facts. Worth testing whether prompt structure or a larger model fixes it —
   and the harness now measures the difference in one command.
2. **Identifier retrieval, still.** Two identifier anchors never reach the top 8. F7 fixed
   the *ranking* of single-half hits; these are not being found by either half.
3. **A harder table.** §2's verdict is only as good as the corpus, and the corpus is polite.
4. **Grading.** If quotation stops being informative, the replacement is a local judge
   under RNF-07 — never a cloud one.
